# Project 14: Document Intelligence Pipeline

Turn messy commercial contracts into **validated JSON records**, and measure how well each extractor does it. Each extracted field carries an **evidence quote** that must appear verbatim in the document, so hallucinated values are caught and removed. A benchmark reports per-field precision and recall, which phrasings fail, and the estimated cost per 1,000 documents for each extractor.

Runs locally with Python's standard library. No install and no API key needed.

## Run

```bash
cd projects/14-document-intelligence
python3 -m app.server          # http://127.0.0.1:8014
python3 -m evals.benchmark     # rules_v1 vs rules_v2 table
python3 -m unittest discover -s evals -t . -v
python3 data/generate.py       # regenerate the synthetic contracts and labels (deterministic)
```

In the UI, choose a sample (try `c003`), choose an extractor, and extract. When a sample is selected, each field is checked against its label.

## The pipeline

```text
contract text --> extractor (rules_v1 | rules_v2 | openai | anthropic)
              --> validation: type, range, evidence grounded in the document
              --> record + per-field status (ok / missing / invalid / ungrounded) + cost estimate
```

| Extractor | What it is | Cost |
|---|---|---|
| `rules_v1` | Naive baseline: first regex match on raw text | free |
| `rules_v2` | Normalizes text, reads sentence by sentence, parses number words, several date formats, negation. **Offline stand-in for a model**, not a model. | free |
| `openai` / `anthropic` | Schema-constrained model call with a field glossary and a stable cacheable prefix | paid |

Fields: effective date, initial term (months), auto-renewal, payment terms (days), termination notice (days), governing law, liability cap (USD, null when relative to fees or absent).

That is the gap a model-based extractor is meant to close, and the point of keeping the unseen category in the benchmark.

## Honest scope

- The contracts are **synthetic and generated by the same author who wrote `rules_v2`**. Its high scores mean "the rules cover the generator", not "this generalizes to real contracts". With CUAD or real contracts, expect much lower numbers.
- **The model extractors (`openai`, `anthropic`) are implemented and unit-tested with a stubbed HTTP call, but were not run against live APIs here, so no model quality numbers are reported.** Run `python3 -m evals.benchmark --extractor openai` with a key to produce them. The run makes about 40 paid calls.
- Input is **text**. The talk's OCR-versus-multimodal comparison needs scanned images; that path (image input to a vision model, compared with OCR plus text extraction) is the next step.
- Cost numbers use illustrative prices in `app/pipeline.py` and about 4 characters per token. Update them before relying on them.
- The grounding check proves the evidence quote exists in the document. It does not prove the value is a correct reading of that quote.

## Cost controls

Document size is capped (60,000 characters at the API, 30,000 sent to a model), output tokens are capped at 600, prompts put the glossary first and the document last for prefix caching, and validation is deterministic code, not a second model call. See the [cost standard](../../docs/COST_OPTIMIZATION.md).
